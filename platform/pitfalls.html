Enterprise Agentic AI Platform

Pitfalls and anti-patterns

As of 2 November 2026 · Mahesh Gupta

The costliest mistakes are rarely technical. Three do the most damage: building the whole platform before any use case proves value, governance that exists on paper but not at runtime, and a platform so slow or rigid that teams route around it and create shadow AI.

Each table lists the anti-pattern, why it hurts, what to do instead, and the early warning sign that it is already happening.

Strategy and funding

Anti-patternWhy it hurtsDo insteadEarly warning sign
Platform before use cases: building all 16 modules before any agent shipsSpend with nothing to show; Gartner found 74% of CIOs already say AI costs match or exceed benefitsShip two or three use cases on the core (modules 1–4), then add modules as needs appearThe roadmap counts modules built, not use cases live
Measuring usage, not valueAdoption charts don't defend a budgetTake a KPI baseline before launch; report cost per business outcomeDashboards show tokens and users but no business metric
Pilot sprawlDozens of proofs of concept, none in production; nothing learned about running AIKill criteria at intake; a cap on concurrent pilotsPilots older than 90 days with no production date
Betting on one vendorModel prices and capabilities shift every few months; lock-in removes leverageReach models through the gateway; build on MCP, A2A and OpenTelemetryApplication code calls a provider's SDK directly

Governance and process

Anti-patternWhy it hurtsDo insteadEarly warning sign
Paper governance: policies written, not enforcedIncidents still happen and audits find gaps; only 34% of organisations have well-defined AI governanceEnforce policy at the gateway and policy engine; generate evidence automaticallyA policy document exists but no runtime rule refers to it
The same approvals for everythingLow-risk work waits weeks, so teams go around the platformRisk tiers, with tier 1 approved the same dayApproval queues lengthen while agents appear outside the registry
Approval theatreReviewers rubber-stamp what they can't assess, giving false assuranceGive reviewers diffs and eval results; sample-audit past approvalsTier 3 approvals completed in minutes
Governance only at launchBehaviour drifts as models, prompts and data changeRe-approve on model changes; review access quarterly; monitor continuouslyNo review after a model swap
A committee that reviews everythingThroughput collapses and the council becomes the bottleneckThe AI council sees tier 3 only; tiers 1–2 are delegatedThe council's backlog runs past a month

Architecture and platform

Anti-patternWhy it hurtsDo insteadEarly warning sign
Point-to-point wiring: each agent connects to its own models and toolsNo single place to apply policy, cost tags or auditRoute every model, tool and agent call through one gatewayProvider API keys sit in application config files
Building every module yourselfSlow and costly, and rarely as good as specialist toolsBuild the core and the glue; buy or reuse the restThe platform team is rebuilding observability or DLP
The platform as one more siloIf it can't read existing tools, teams keep their own and route around itPlug in through open standards; connect to ITSM, GRC and the identity providerTeams keep separate tooling because the platform can't do something
Hard-coding one organisation's processThe next line of business or client needs a different approval chainKeep processes as configuration: workflow definitions and policy as codeChanging an approval step needs a code release
Treating moving standards as settledOpenTelemetry's GenAI conventions are still marked Development; renamed fields break dashboardsPin versions and keep an adapter layerRaw field names are used directly across many services

Security, identity and data

Anti-patternWhy it hurtsDo insteadEarly warning sign
Shared keys, or agents running on a broad service accountOne leak exposes everything, and no action can be traced to an agentA separate identity per agent; short-lived, scoped tokensThe same key appears in several agents
Token passthrough: forwarding the user's own token downstreamAny compromised hop gets the user's full rights; the MCP specification forbids itExchange tokens at every hop for a narrower one naming user and agentDownstream services receive the user's original token
Indexing before classifyingRetrieval surfaces confidential data to people who should never see itLabel sources first; retrieval uses the end user's permissionsA vector index built from "everything in SharePoint"
Treating retrieved content as instructionsPrompt injection arrives through documents, emails, tool output and tampered Agent CardsTreat all retrieved content as data; accept only signed cards from your registry; run runtime defenceAn agent acts on an instruction found in an email or web page
Unknown agents in productionYou can't govern what you can't see; 82% of enterprises found unknown agents in production (CSA and Token Security)Discovery plus registration before any access is grantedSecurity finds agents that aren't in the registry
No kill switchA misbehaving agent keeps running while people find the right leverA tested switch for every agent, tool and modelStopping an agent needs a redeploy
Logging every prompt in fullPersonal data lands in logs with long retentionCapture content by data label; redact the restTraces contain personal data

Agents and agent-to-agent

Anti-patternWhy it hurtsDo insteadEarly warning sign
Too much autonomy too earlyIrreversible mistakes such as payments, deletions or customer messagesStart with drafts; require human approval for irreversible actions; widen autonomy as evidence buildsA first release executes payments or deletes without approval
Agent sprawlNear-duplicate agents multiply cost, confuse users and split maintenanceSearch the registry before building; reuse and extendFive different "HR policy" agents
An agent mesh nobody ownsFailures can't be traced, loops burn tokens, and no one fixes the chainAn owner per agent; one trace ID across hops; limits on call depth and budget per chainTraces with unexplained hops; sudden token spikes from loops
Permanent agent-to-agent grantsAccess accumulates long after the need has goneGrants expire and are recertifiedGrants older than a year still active

Cost

Anti-patternWhy it hurtsDo insteadEarly warning sign
Untagged callsSpend can't be attributed, and the CFO stops trusting the numbersEnforce the four tags at the gateway; reject untagged callsThe "unallocated" share of the AI bill keeps growing
The largest model for every taskCosts multiply for work a smaller model handles equally wellRoute by task, cache repeated requests, and test cheaper models against the evalsOne premium model serves every agent
No hard capsA looping agent or a bad release burns a month's budget in a dayBudgets and caps per agent, team and line of business, with alerts in hoursSpend is found at month end, not the same day
Coding-agent seats outside the viewA large, growing cost sits in a separate contract nobody compares with outputShow seats and usage beside API spend and delivery metricsLicences unused after 60 days

Quality and observability

Anti-patternWhy it hurtsDo insteadEarly warning sign
Shipping on demosRegressions reach users because nothing measured quality before releaseGolden datasets, evals in CI, and sampling of live answersReleases go out without eval results attached
Prompts hidden in codeChanges can't be traced, reviewed or rolled backKeep prompts in the prompt hub, versioned and linked to tracesPrompt edits in production with no record
Watching only latency and uptimeWrong, ungrounded or unsafe answers stay invisibleUse the full metrics catalogue: groundedness, approvals, guardrail hits, feedbackThe dashboard is green while users complain
No feedback loopThe same failures repeatTurn every flagged answer into an eval caseRepeated tickets about the same wrong answer

Delivery and adoption

Anti-patternWhy it hurtsDo insteadEarly warning sign
Counting AI-written code as productivityMore code isn't faster delivery: DORA describes a "verification tax" of reviewing generated code, and AI-assisted pull requests reportedly wait about 2.5 times longer for reviewMeasure cycle time, change-failure rate and review wait, not lines or pull requestsPull request counts rise while lead time stays flat
Rollout without enablementLow adoption and risky use from people who were never shown howTraining tied to access, a champions network and an adoption leadTools unused 60 days after rollout
Ignoring workforce concernsResistance and quiet non-use; employee-relations issuesInvolve the CHRO early; be open about how roles changeStaff avoid tools or use personal accounts instead
No platform product ownerThe platform becomes a technical project with no customers or prioritiesA product owner with a backlog, roadmap and internal NPSFeatures nobody asked for; requests with no home

Configurability

Anti-patternWhy it hurtsDo insteadEarly warning sign
Making everything configurableUntestable combinations, support load and confused usersA small set of settings with good defaults and starter profilesSettings nobody has ever changed
Letting teams loosen settingsThe weakest team sets the whole organisation's riskTighten-only inheritance; exceptions with an owner and an expiryTeams with lower eval marks or longer retention than the organisation
Exceptions that never expirePolicy changes by stealthEvery exception expires and is visible to the CISO and the LOB headExceptions past their expiry date still active
Bring-your-own tools that skip the contractOne line of business's gap breaks cost, audit and security views for allRun contract conformance tests before a tool is plugged inCalls from one line of business arrive without tags or traces
